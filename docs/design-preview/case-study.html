The first question is context.

Which branch failed? What changed in its configuration? Which account am I actually investigating? Answering an operational question can mean moving between several screens before the evidence comes together.

I built amplify-ops within BotoToolkit to make that investigation explicit. The tool checks identity, keeps resource scope visible, and distinguishes incomplete reads from complete results.

From identity to a reviewed action

Open each step to see the behavior behind the interface. Investigation remains useful even when no retry is needed.

1Establish identity

The operator supplies a profile, an expected AWS account, and selected regions. An STS identity check runs before operational reads, helping catch work in the wrong environment.

2Investigate the deployment

Collect Amplify Hosting inventory and deployment evidence within the selected scope. Contextual errors and meaningful exit codes make partial reads visible.

3Compare configuration

Report configuration differences while withholding the underlying values. The operator can identify a mismatch without casually exposing configuration in the report.

4Review a retry, if needed

The deployment command submits an explicitly reviewed retry. This transition is separate from the read-only operational commands and is optional.

Decisions that shape the tool

Identity comes first.

Account context is an input to the investigation. Checking it early reduces the chance of confidently investigating the wrong environment.

Scope stays visible.

Amplify Hosting inventory does not claim to discover every backend dependency. Reports should help an operator judge what was actually read.

Useful differences, withheld values.

Configuration comparison surfaces changes while keeping the values themselves out of the report.

Incomplete evidence is explicit.

A partial read must remain distinguishable from an empty or complete result. Error context is part of the interface.

Inspect the implementation

The public repository contains the CLI, command documentation, uv lockfile, and pytest checks. Its CI configuration includes Linux and Windows tests, sensitive-information checks, and distribution smoke checks.

Scope & limitations

This case study covers an independent tool for Amplify Hosting operations in selected accounts and regions. CI authentication support is documented as future work. No uptime or productivity improvements are claimed here.

The principle carries into delivery.

BotoToolkit verifies a local operator’s identity. This portfolio’s delivery pipeline uses a separate mechanism, GitHub OIDC, to establish a workflow’s AWS identity. Both make the boundary between identity and permission explicit.
